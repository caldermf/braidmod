# Learning Braid Group Representations

## 1. Project Goal

This project is a mechanistic interpretability case study for a small but
nontrivial algebraic learning problem.

We work first in the braid group `B_3`. The model sees only the reduced Burau
representation matrix of a braid over `(Z/2)[v, v^{-1}]`. From that matrix
alone, it must predict whether the right descent set of the final Garside
factor is `{s_1}` or `{s_2}`.

The point is not just to train a high-accuracy classifier. The point is to
understand, in detail, what algorithm a small transformer learns when it solves
this task. We want to recover a concrete internal computation: which features of
the polynomial matrix are used, where those features are represented, and how
they are converted into the final descent decision.

This `B_3` project is the clean first step toward the larger `B_4` Burau
interpretability project. `B_4` is mathematically richer and ultimately more
important, but `B_3` gives us a smaller setting where the full mechanistic story
has a much better chance of being visible.

## 2. Mathematical Setup

The braid group `B_3` is generated by `s_1` and `s_2`, subject to the braid
relation

```text
s_1 s_2 s_1 = s_2 s_1 s_2.
```

We use the Garside normal form of a braid. A braid is represented as

```text
Delta^d w_1 w_2 ... w_L,
```

where each `w_k` is a simple Garside factor. For this first experiment, every
sample will have fixed Garside length

```text
L = 25.
```

The supervised label is determined only by the final simple factor `w_L`. Its
right descent set is the set of generators that can appear as a right descent of
that factor.

For the binary version of this experiment, we use examples whose final descent
set is exactly one of

```text
{s_1}
{s_2}
```

The model's task is therefore:

```text
Burau matrix of braid -> final descent is {s_1} or {s_2}
```

We deliberately avoid using the braid word or the Garside factors as model
input. Those are metadata for supervision, auditing, and interpretation. The
model receives only the Burau representation matrix.

The reduced Burau representation of `B_3` gives a `2 x 2` Laurent polynomial
matrix. We work over `(Z/2)[v, v^{-1}]`, so every coefficient is binary. This
keeps the first setting maximally clean: the model must use polynomial support,
degree structure, and matrix-entry structure, not signs or large coefficients.

## 3. Dataset

The first dataset should be large, fixed-length, and easy to audit.

Target dataset:

```text
group:             B_3
Garside length:    25
coefficient ring:  (Z/2)[v, v^{-1}]
input object:      reduced Burau matrix
matrix size:       2 x 2
task:              binary classification, {s_1} vs {s_2}
```

Each record should contain:

```text
burau_tensor:          D x 2 x 2 binary coefficient tensor
burau_min_degree:      integer projective degree shift
label:                 0 for {s_1}, 1 for {s_2}
final_descent:         "s1" or "s2"
gnf_d:                 Delta exponent
gnf_factors:           full Garside factor list
final_factor_perm:     final simple factor
garside_length:        25
seed:                  generation seed or stream identifier
```

The tensor should be projectively normalized in the same spirit as the existing
`B_4` pipeline:

1. Compute the reduced Burau matrix over `(Z/2)[v, v^{-1}]`.
2. Find the smallest exponent appearing anywhere in the matrix.
3. Shift all exponents so the minimum occupied degree becomes `0`.
4. Store the stripped minimum degree separately as `burau_min_degree`.
5. Store the normalized coefficient tensor with fixed depth `D`.

The dataset generator should also run basic audits:

- Check that every generated Garside normal form has length `25`.
- Check that the final descent is exactly `{s_1}` or `{s_2}`.
- Check class balance.
- Group identical normalized Burau tensors, including `burau_min_degree`, and
  verify that no identical input has conflicting labels.
- Save a small manifest with generation settings, counts, class balance, and
  collision statistics.

The first version should use `p = 2`. After the `B_3, p = 2` mechanism is
understood, repeat the same experiment for `p = 3` and `p = 5` as robustness
checks.

## 4. Model

Train a deliberately small transformer. The model should be large enough to
learn the task but small enough to interpret.

Input:

```text
burau_tensor:      D x 2 x 2
burau_min_degree:  scalar
```

Output:

```text
one binary logit: final descent is {s_2} rather than {s_1}
```

A natural architecture is a reduced version of the existing polynomial matrix
transformer:

- Embed each coefficient value, matrix row, matrix column, and polynomial degree.
- For each degree slice, encode the `2 x 2` matrix entries.
- Use a global transformer over degree slices.
- Add a learned projection of `burau_min_degree`.
- Read out a binary classification logit from a final summary token.

Keep the first model intentionally modest. A good starting point is:

```text
d_model:             64 or 128
local blocks:        1
global blocks:       2 to 4
attention heads:     2 to 4
dropout:             low or zero after the baseline is stable
loss:                binary cross-entropy with logits
selection metric:    validation accuracy and validation loss
```

Baselines are mandatory. Train or evaluate:

- Majority-class baseline.
- Logistic regression or linear probe on flattened tensors.
- Small MLP on flattened embedded tensors.
- Transformer without `burau_min_degree`.

These baselines are important because if the task is linearly solvable, the
interpretability target changes. In that case, the result should be framed as
recovering a simple algebraic feature rather than reverse-engineering a complex
transformer algorithm.

## 5. Mechanistic Interpretability Program

The core research goal is to explain the trained transformer.

We want to know whether it learns something like:

- a direct polynomial support rule,
- a degree-boundary or valuation-based rule,
- a hidden representation of the final simple Garside factor,
- an automaton-like update over possible Garside states,
- or some shortcut specific to length `25` and characteristic `2`.

The interpretability work should proceed in stages.

### 5.1 Behavioral Characterization

Measure model behavior before opening the model.

- Accuracy by class.
- Accuracy by final simple factor.
- Accuracy by polynomial support width.
- Accuracy by `burau_min_degree`.
- Generalization to nearby lengths, such as `20`, `24`, `26`, and `30`.
- Robustness to `p = 3` and `p = 5` after the `p = 2` case is understood.

### 5.2 Representation Probing

Use activation caches and linear probes to ask what information appears where.

Probe for:

- final descent label,
- full final simple factor,
- polynomial support width,
- minimum and maximum occupied degree,
- selected entries of the leading and trailing coefficient matrices,
- Garside-state information from intermediate factors, if recoverable.

The most important question is whether the model internally represents more
than the supervised binary label. If a descent-only model contains a linearly
recoverable final-factor representation, that would be strong evidence that it
learned a richer algebraic structure.

### 5.3 Causal Interventions

Move beyond correlation with causal tests.

Use:

- activation patching between correct and incorrect examples,
- patching between `{s_1}` and `{s_2}` examples,
- head ablations,
- MLP-block ablations,
- residual-stream patching by layer and degree position,
- targeted corruption of degree slices or matrix entries.

The goal is to identify which components are necessary for the decision and
which components merely correlate with it.

### 5.4 Feature and Circuit Recovery

After locating important components, try to translate them into mathematics.

Candidate outcomes:

- A small set of degree slices controls the decision.
- The model reads off a leading or trailing matrix pattern.
- The model computes a proxy for the final simple factor.
- The model implements a finite-state classifier over possible Garside suffixes.
- The model uses `burau_min_degree` in a specific, causal way.

The strongest result would be a hand-coded classifier, derived from the
interpreted circuit, that matches the transformer's predictions and then matches
the true labels.

## 6. Success Criteria

A minimal successful project has:

- A reproducible `B_3`, length-`25`, `(Z/2)[v, v^{-1}]` dataset.
- A small transformer that solves the binary descent task.
- Baselines showing whether the task is trivial, linear, or genuinely nonlinear.
- Collision and label-consistency audits.
- Activation probes showing what information the model represents.
- Causal interventions identifying which layers, heads, tokens, or features
  drive the classification.
- A clear hypothesis for the learned algorithm.

A strong project has:

- A recovered human-readable algorithm.
- A hand-coded classifier inspired by the circuit.
- Evidence that the same mechanism, or a close analogue, appears for `p = 3`
  and `p = 5`.
- A clear bridge from the `B_3` mechanism to the larger `B_4` setting.

## 7. Why Start With B_3?

`B_4` is the larger target, but it is harder to interpret. Its reduced Burau
matrix is `3 x 3`, its final factor has many more possibilities, and the model
can hide information in a larger representation space.

`B_3` is the right first microscope:

- The matrix is only `2 x 2`.
- There are only two generators.
- The binary descent task is easy to state.
- Exhaustive and near-exhaustive audits are realistic.
- The Burau representation is faithful in this setting.
- Characteristic `2` makes coefficients binary, simplifying the input space.

This simplicity is a feature, not a weakness, as long as we treat `B_3` as the
first interpretability target rather than the final mathematical destination.
If we can recover the learned algorithm in `B_3`, we will have a concrete
template for attacking the richer `B_4` transformer.

## 8. First Milestones

1. Implement a `B_3` dataset generator under `interp/`.
2. Generate a small smoke-test dataset and run all audits.
3. Generate the large length-`25`, `p = 2` dataset.
4. Train baselines.
5. Train the small transformer.
6. Build activation-caching utilities.
7. Run probes and ablations.
8. Attempt circuit-to-algorithm translation.
9. Repeat key checks for `p = 3` and `p = 5`.
10. Decide whether the recovered mechanism is ready to port to `B_4`.
